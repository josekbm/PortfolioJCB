## 1. Resumen ejecutivo

La web aprueba las auditorías automáticas de Lighthouse (SEO 100), pero eso **no mide lo que importa**: el HTML inicial está vacío y, tras ejecutar JavaScript, solo hay **170 palabras (EN) / 177 (ES), 0 encabezados y 1 enlace** (el PDF del CV). No hay ningún enlace interno HTML: el selector de idioma es un `<button>`.

Cuatro de las seis secciones (Servicios, Proyectos, Skills y Contacto) no se montan en el DOM hasta que el usuario las abre desde el Dock o con un comando de la terminal.

Conclusión: el problema no es de etiquetas meta, es de **arquitectura de contenido**. Hay 2 URLs canónicas en el sitemap y el contenido comercial no existe para un crawler que no interactúa.

Notas de método:

- Lighthouse se ejecutó solo con datos de laboratorio (lab). No hay datos de campo CrUX en este baseline.
- No se pudo usar la API de PageSpeed Insights (cuota 0 sin API key). GSC y Bing requieren acceso a la cuenta.

- `src/os/Desktop.tsx` (commit `039e839`): `if (!state.open) return null;` — una sección cerrada no se renderiza.

- `src/os/BootSequence.tsx`: 150 ms iniciales + 10 intervalos × 130 ms + 700 ms finales ≈ **2,15 s** (11 líneas) antes de montar el escritorio en cada sesión nueva.

## 5. Objetivo de la Fase 1 (quick wins)

1. `<h1>` real en la ventana About + fallback `<noscript>`.
2. Metadatos ajustados a límites SERP.
3. JSON-LD base: `Person`, `WebSite`, `ProfessionalService`.
4. Servidor: 301 de `www`, 404 real, HSTS, cabeceras de seguridad también en `/assets/`.
5. Puente temporal: renderizar las 6 ventanas en el DOM y ocultar las cerradas.
6. Eliminar `meta keywords` y añadir `max-image-preview:large`.

Criterio de aceptación: el DOM renderizado contiene las 6 secciones, hay exactamente 1 `<h1>`, los validadores de datos estructurados pasan y `curl` confirma 404/301/HSTS/cabeceras de assets.

## 9. Reproducibilidad

- `docs/seo/baseline/reproduce.sh`: cabeceras, canonical, 404, `www`, gzip y Lighthouse 13.6.0.
- `docs/seo/baseline/metrics.cjs`: conteo exacto de palabras, encabezados y enlaces con Puppeteer.

- Los JSON de Lighthouse y el DOM quedan en `docs/seo/baseline/`.

Ejemplo:

```bash
# Desde el árbol actual, contra la versión desplegada del baseline.
# Los scripts viven en este árbol; 039e839 identifica el código medido.
CHROME_PATH="/ruta/a/chrome" \
  NODE_PATH="/tmp/seo-tools/node_modules" \
  bash docs/seo/baseline/reproduce.sh
```

Si el sitio ya está desplegado con la Fase 1, usa los artefactos guardados en `docs/seo/baseline/` (la reproducción en vivo ya no aplicaría al baseline).
